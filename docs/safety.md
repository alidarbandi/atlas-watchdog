# Read-only access and coverage limits

The observational source reader uses `CreateFileW` with **GENERIC_READ**, **FILE_SHARE_READ | FILE_SHARE_WRITE | FILE_SHARE_DELETE**, and **OPEN_EXISTING**. It never requests write access, creates a missing source, uses a byte-range lock, maps a source into memory, or retains a handle between polls. Size and identity come from that open handle; directory size/mtime is not a prerequisite to reading. Bounded source bytes are copied, and the handle closes before parsing, SQLite, GUI or network work.

Reference: Microsoft's [CreateFileW sharing/access contract](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew), [GetFileSizeEx](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfilesizeex), and [explanation of stale directory file sizes](https://devblogs.microsoft.com/oldnewthing/20111226-00/?p=8813). The wrapper declares ctypes argument and return types explicitly, including 64-bit handles and offsets; see [Python ctypes](https://docs.python.org/3.12/library/ctypes.html).

**Sharing flags cannot override ATLAS denying readers. An ATLAS exclusive reopen can conflict while our brief read handle is outstanding. Absolute zero interference is not promised.** Real Windows tests demonstrate shared writer access and the exclusive-access limitation; microscope startup/shutdown/rotation must still be tested with an expendable acquisition before unattended use.

On missing file, access denial, sharing violation or transient read error, the application reports source health and retries on schedule without bypassing protection or tight retry loops. Such a read is not a successful empty poll. Neither the reader nor any test attempts to flush vendor handles, modify settings, suspend ATLAS, restart a process or control the microscope.

All configuration, state, diagnostics and exports are outside selected source folders and both known ATLAS folder spellings. Export validation rejects a monitored file, aliases resolving to it, and source/configuration directories. No source-directory write permission or administrator elevation is required. Source-reader tests use temporary files only; the demo writer also uses its own dedicated directory. Original sample files are references only.

Coverage remains best effort. Immediate reads cannot recover bytes not yet written by ATLAS, overwritten data, an unread renamed tail without an established rotation convention, or a file wholly created/removed between polls. File identity and boundary verification improve replacement/rewrite detection without promising archival recovery. Checkpoint durability assumes the local state store is usable. Storage failure has a visible degraded-reliability state and bounded emergency memory; do not rely on unattended persistence until repaired.

This desktop process cannot report immediately if its PC loses all power, the OS fails, the process crashes, or all network access is lost. Sleep/logout interrupt coverage. A future external-heartbeat design would need a separately chosen external observer; no service, paid endpoint or hardcoded heartbeat recipient is enabled here.

Normal traffic is limited to configured notification endpoints and explicit setup/tests. There is no default telemetry, whole-log upload, hosted control server, remote support channel, automatic updater, inbound listening port or microscope command listener. Respect laboratory firewall/proxy and execution policy; never disable TLS verification or antivirus protections to run this utility.
